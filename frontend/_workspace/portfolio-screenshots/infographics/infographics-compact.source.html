쇼핑 추천 에이전트

기록을 근거로 상품을 고르는
LangGraph workflow

LLM 판단과 외부 검색이 여러 단계로 이어져 각 단계를 노드로 분리

INPUT프로필 · 기록 · 케어 제안
↓
1
prepare_categories
LLM이 기록을 읽고 검색 카테고리·검색어 생성
↓
2
search_products
Naver Shopping API로 카테고리별 후보 검색
↓
3
select_recommendations
상위 3개 후보 중 LLM이 1개 선택 + 추천 이유 생성
↓
4
build_result
추천 목록 확정
↓
OUTPUT상품명 · 최저가 · 판매처 · 추천 이유 카드

fallback · 카테고리 실패 → 추천 없이 종료 · 검색 실패 → 규칙 기반 검색 · 선택 실패 → 첫 후보 유지

병원 추천

규칙 기반으로 안전을 우선하는
provider · middleware 구조

단계가 짧고 안전 규칙이 핵심이라 LangGraph 없이 단순하게 유지

INPUT현재 위치 · 증상 메모
↓
1
응급 여부 판단
22~06시 또는 응급·호흡·출혈·경련 등 키워드 감지
↓
2
반경 · 검색어 조정
응급이면 반경 10km · 검색어 "24시 동물병원"
↓
3
Google Places 검색
앞단에 캐시 10분 · 분당 30회 rate limit middleware
↓
4
정렬 · 필터
24시간 → 진료 중 → 평점 → 리뷰 수 → 거리 순
↓
OUTPUT지도 마커 · 거리 · 운영 상태 병원 후보

fallback · 검색 실패나 API key 누락 시 Google Maps 검색 링크로 다음 행동 안내
