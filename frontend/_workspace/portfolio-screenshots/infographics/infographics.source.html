쇼핑 추천 에이전트

기록을 근거로 상품을 고르는 LangGraph workflow

LLM 판단과 외부 검색 API가 여러 단계로 이어지기 때문에 각 단계를 노드로 분리했습니다.

INPUT
프로필 · 기록 · 케어 제안
반려동물 프로필과 최근 식사·산책·배변·행동 기록을 입력으로 받습니다.
↓
NODE 1
prepare_categories
LLM이 기록을 읽고 검색 카테고리와 검색어를 생성합니다.
실패 시 빈 카테고리 → 추천 없이 안전 종료
↓
NODE 2
search_products
Naver Shopping API로 카테고리별 상품 후보를 검색합니다.
API 실패 시 규칙 기반 네이버 검색 fallback
↓
NODE 3
select_recommendations
검색어별 상위 3개 후보 중 LLM이 1개를 선택하고 추천 이유를 붙입니다.
선택 실패 시 첫 번째 후보 유지
↓
NODE 4
build_result
선택된 추천 목록을 최종 결과로 확정합니다.
↓
OUTPUT
추천 카드
상품명 · 최저가 · 판매처 · 기록 근거 추천 이유가 담긴 카드로 화면에 표시됩니다.

단계마다 fallback 경계를 명시해, 외부 API나 LLM이 실패해도 화면 흐름이 끊기지 않습니다.

병원 추천

규칙 기반으로 안전을 우선하는 provider · middleware 구조

단계 수가 짧고 의료 안전 규칙이 핵심이라, LangGraph 대신 application agent + provider/middleware 조합으로 단순하게 유지했습니다.

INPUT
현재 위치 · 증상 메모
보호자 위치 좌표와 증상 텍스트를 입력으로 받습니다.
↓
STEP 1
응급 여부 판단
22시~06시이거나 증상에 응급 · 야간 · 24시 · 호흡 · 출혈 · 경련 · 중독이 있으면 응급 모드로 전환합니다.
↓
STEP 2
검색 반경 · 검색어 조정
응급이면 반경을 최소 10km로 넓히고 검색어를 "24시 동물병원"으로 바꿔 24시간 병원만 남깁니다.
↓
STEP 3
Google Places 검색
앞단에 캐시 10분 · 분당 30회 rate limit middleware를 두어 외부 호출을 제어합니다.
검색 실패·키 누락 시 Google Maps 검색 링크 fallback
↓
STEP 4
정렬 · 필터
24시간 운영 → 진료 중 → 평점 → 리뷰 수 → 거리 순으로 정렬합니다.
↓
OUTPUT
병원 후보 목록
지도 마커와 거리·소요시간·운영 상태로 표시하고, 선택하면 병원 상담 준비 흐름으로 이어집니다.

진단을 단정하지 않고, 위험 신호가 있을 때 병원 상담으로 연결하는 안전 경계를 유지합니다.
